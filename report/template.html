מודל נכון לכל שלב: הסקיל נשלף פי מהר יותרThe right model for each step: the skill is fetched × faster

התזה: משימה עם כמה שלבים לא צריכה לרוץ כולה על אותו מודל גדול. אם מפרקים אותה ונותנים כל שלב לסוג המודל שמתאים לו, אפשר לקצר מאוד את הזמן עד התשובה.The thesis: a task with several steps doesn't have to run entirely on one large model. Split it, give each step to the kind of model that fits it, and the time to the answer can drop a lot.

בדקתי את זה על מקומיmekomIL, ה־skill שנותן ל־Claude גישה לקטלוג skills-il. לפני ש־Claude עונה על שאלה ישראלית, הוא צריך להחליט אם לטעון skill מקטלוג של 218, ואיזה. זה שלב של החלטה, לא של כתיבה, אז נתתי אותו ל־Jev, מודל החלטות קטן, ומדדתי כמה זמן לוקח עד שה־skill הנכון נשלף.I tested it on מקומיmekomIL, the skill that gives Claude access to the skills-il catalog. Before Claude answers an Israeli question, it has to decide whether to load a skill from a catalog of 218, and which one. That step is a decision, not writing, so I gave it to Jev, a small decision model, and measured how long it takes until the right skill is fetched.

שני מסלוליםTwo routes

53 שאלות בעברית מסט הבדיקה של מקומי IL, כל אחת 3 פעמים בכל מסלול. Claude הוא Sonnet 5.5 במאמץ high, עם אותם כלים ואותו system prompt בשני המסלולים.53 Hebrew questions from mekomIL's test set, each run 3 times per route. Claude is Sonnet 5.5 at high effort, with the same tools and system prompt in both routes.

והאם נשלף ה־skill הנכון?And was it the right skill?

מהירות לא שווה הרבה אם ה־skill שגוי. בשאלות שצריכות skill, מסלול 2 שלף את ה־skill הנכון בתדירות דומה ל־Claude לבד.Speed is worth little if the skill is wrong. On questions that need a skill, route 2 fetched the right skill about as often as Claude alone.

מה זה אומרWhat it means

  • החיסכון מגיע מהסבבים. Claude לבד עושה כ־4 סבבים של חשיבה וקריאת כלים כדי לנווט בקטלוג. Jev מקבל את ההחלטה הזאת בשלוש קריאות קצרות, ו־Claude צריך סבב אחד בלבד.The savings come from rounds. Alone, Claude takes about 4 rounds of thinking and tool calls to navigate the catalog. Jev makes that decision in three short calls, and Claude needs a single round.
  • Claude מקבל את ההחלטה. בכל הריצות הוא שלף בדיוק את ה־skill ש־Jev בחר, בלי לבדוק שוב את הקטלוג.Claude accepts the decision. In every run it fetched exactly the skill Jev chose, without checking the catalog again.
  • איפה זה עוזר ואיפה לא: מסלול 2 היה מהיר יותר בכל 40 השאלות שצריכות skill. אבל ב־9 מתוך 13 השאלות שלא צריכות skill הוא היה איטי יותר, כי שם Claude לבד עונה ישר בלי כלים, ו־Jev רק מוסיף זמן. פירוק לשלבים משתלם כשיש שלבים לחסוך.Where it helps and where it doesn't: route 2 was faster on all 40 questions that need a skill. But on 9 of the 13 questions that need no skill it was slower, because there Claude alone answers right away without tools and Jev only adds time. Splitting into steps pays off when there are steps to save.
  • גבולות: נמדד רק שלב הניתוב, לא התשובה המלאה. 53 שאלות בלבד, ואותן שאלות שימשו לפיתוח שלבי הניתוב של Jev, אז את הדיוק כדאי לאשש על שאלות חדשות. הכלים של מקומי IL הם העתק מקומי של הקטלוג.Limits: only the routing step is measured, not the full answer. Just 53 questions, and the same questions were used to develop Jev's routing steps, so the accuracy should be confirmed on new questions. The mekomIL tools are a local copy of the catalog.

הערה: זה ניסוי, לא שינוי במקומי ILA note: this is an experiment, not a change to mekomIL

מקומי IL בנוי לשימוש יומיומי ושקוף. שואלים כרגיל, וכשיש skill מתאים הוא נטען בלי שצריך לחשוב על זה. כשאין, הוא לא מפריע. הוא לא נועד למהירות תגובה אלא לתשובה יסודית ונכונה, ולכן כמה שניות של חיפוש בקטלוג הן מחיר סביר תמורת תשובה מקומית ומדויקת. מקומי IL עובד עם עוזר ה־AI שהמשתמש כבר עובד איתו, Claude או ChatGPT, וגם העובדה שהעוזר שוקל בעצמו אם ואיזה skill לטעון היא חלק מהיסודיות הזאת. בניסוי השתמשתי ב־Claude, אבל אותו עיקרון נכון גם ל־ChatGPT.mekomIL is built for everyday, seamless use. You ask as usual, and when a skill fits it loads without you thinking about it. When none fits, it stays out of the way. It isn't optimized for response time but for a thorough, correct answer, so a few seconds of catalog lookup are a fair price for a local, accurate answer. mekomIL works with the AI assistant the user already uses, Claude or ChatGPT, and the assistant weighing for itself whether and which skill to load is part of that thoroughness. The experiment used Claude, but the same applies to ChatGPT.

שינוי הארכיטקטורה כאן נועד להדגים נקודה אחת: שכשמפרקים משימה עם כמה שלבים ונותנים כל שלב לסוג המודל שמתאים לו, אפשר לקצר מאוד את הזמן עד התשובה. מקומי IL היה מקרה בדיקה נוח, כי יש לו שלב החלטה ברור וסט שאלות מתויג. השינוי לא משרת את מטרת הסקיל, ומקומי IL לא עובר לארכיטקטורה הזאת.The architecture change here exists to demonstrate one point: when you split a multi-step task and give each step to the kind of model that fits it, the time to the answer can drop a lot. mekomIL was a convenient test case because it has a clear decision step and a labeled question set. The change doesn't serve the skill's goal, and mekomIL is not moving to this architecture.

פרטיות. אחד היתרונות של מקומי IL הוא ששרת ה־MCP שלו רק מגיש קבצים: הוא מקבל שם של קטגוריה או של skill, ואף פעם לא את השאלה של המשתמש. השאלה נשארת בשיחה עם העוזר, Claude או ChatGPT. ניתוב דרך Jev היה שולח כל שאלה של כל משתמש קודם כל לספק נוסף, וזה פוגע בפרטיות שהסקיל שומר עליה בכוונה.Privacy. One of mekomIL's strengths is that its MCP server only serves files: it receives a category or skill name, never the user's question. The question stays in the conversation with the assistant, Claude or ChatGPT. Routing through Jev would send every user's question to an additional provider first, which undoes the privacy the skill deliberately keeps.
